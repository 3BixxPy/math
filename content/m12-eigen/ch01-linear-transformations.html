Chapter 1 · concept:linear-transformation-definition

Linear Transformations

Module 11's capstone closed out vector spaces in the abstract. This module puts them back to work: every rotate, scale, and reflect you've ever called on a game object is about to get a name, a precise test, and — by Chapter 6 — a way to find the one direction it doesn't secretly rotate.

Why this matters

You've called transform.Rotate(90, Vector3.up), or multiplied a mesh's vertices by a scale matrix, or flipped a sprite with transform.localScale.x *= -1, more times than you can count. Every one of those is a function that eats a vector (a vertex position, a direction) and hands back another vector. Not every such function deserves to be called "linear," though — and the ones that do are exactly the ones an engine can represent as a single matrix, compose by multiplying, and — this module's whole point — analyze for the directions they only stretch and never rotate. This chapter draws the line between "linear" and "everything else," precisely enough to test it in two lines of algebra.

Definition — Linear transformation

A function \(T\) (taking vectors to vectors) is a linear transformation if, for every pair of vectors \(u,v\) and every scalar \(c\), both of the following hold:

\[ T(u+v) = T(u) + T(v) \qquad\text{and}\qquad T(cu) = cT(u) \]
(12.1.1)

The first condition is called additivity — transforming a sum gives the same result as transforming each piece and adding afterward. The second is homogeneity — transforming a scaled vector gives the same result as scaling the transformed vector. Together, these two properties — "preserves addition" and "preserves scalar multiplication" — are the entire content of the word "linear." Nothing about lines, slopes, or graphs is implied; it's purely about which structural properties the function respects.

One useful corollary falls out immediately: set \(c=0\) in the homogeneity condition. Then \(T(0\cdot u) = 0\cdot T(u)\), which simplifies to \(T(\vec 0) = \vec 0\). Every linear transformation sends the zero vector to the zero vector. That's a necessary condition, not a sufficient one — but because it's so cheap to check, it's the fastest possible first test for ruling a candidate out.

Worked example — confirming a transformation IS linear

Let \(T(\langle x,y\rangle) = \langle 2x, 2y\rangle\) — uniform scaling by a factor of 2, exactly what transform.localScale = Vector3.one * 2 does to every vertex of a mesh. Verify both conditions of Definition 12.1.1.

Step 1 — check additivity

Let \(u=\langle x_1,y_1\rangle\), \(v=\langle x_2,y_2\rangle\), so \(u+v=\langle x_1+x_2,\ y_1+y_2\rangle\).

\(T(u+v) = \langle 2(x_1+x_2),\ 2(y_1+y_2)\rangle = \langle 2x_1+2x_2,\ 2y_1+2y_2\rangle\)

\(T(u)+T(v) = \langle 2x_1,2y_1\rangle + \langle 2x_2,2y_2\rangle = \langle 2x_1+2x_2,\ 2y_1+2y_2\rangle\)

The two sides match exactly, for any \(u,v\) — additivity holds.

Step 2 — check homogeneity

\(T(cu) = T(\langle cx_1,cy_1\rangle) = \langle 2cx_1,\ 2cy_1\rangle\)

\(cT(u) = c\langle 2x_1,2y_1\rangle = \langle 2cx_1,\ 2cy_1\rangle\)

These match too, for any scalar \(c\) — homogeneity holds.

Result

Both conditions hold for every choice of \(u,v,c\), so \(T\) is a linear transformation. Uniform scaling is linear — no surprise, but now it's proven, not just assumed.

Worked example — confirming a transformation is NOT linear

Let \(T(\langle x,y\rangle) = \langle x+1,\ y\rangle\) — a translation, shifting everything 1 unit right. Is it linear?

Step 1 — run the fast disqualifying test first: does T(0) = 0?

\(T(\langle 0,0\rangle) = \langle 0+1,\ 0\rangle = \langle 1,0\rangle \neq \langle 0,0\rangle\).

The corollary from Definition 12.1.1 said every linear transformation must send the zero vector to itself. This one sends it to \(\langle1,0\rangle\) instead — T already fails, and there's no need to check the full additivity/homogeneity conditions at all.

Step 2 — confirm directly, for completeness

Let \(u=\langle1,0\rangle\), \(v=\langle1,0\rangle\), so \(u+v=\langle2,0\rangle\).

\(T(u+v) = T(\langle2,0\rangle) = \langle3,0\rangle\), but \(T(u)+T(v) = \langle2,0\rangle+\langle2,0\rangle = \langle4,0\rangle\).

\(\langle3,0\rangle \neq \langle4,0\rangle\) — additivity genuinely fails, confirming what the fast test already showed.

Result

\(T\) is not a linear transformation. Geometrically this makes sense: a translation slides the entire plane without fixing the origin in place, while every linear transformation — rotation, scaling, reflection, shearing — leaves the origin exactly where it is (in engine terms: it transforms a mesh's local-space vertices, all measured from a shared local origin, which is precisely why transform.Rotate or a scale matrix never needs to also carry a separate "move by this much" offset the way a translation does).

Common mistake

Assuming any "reasonable-looking" function of a vector is automatically linear. Translations are the single most common near-miss — anything of the form "add a fixed nonzero vector" fails, because \(T(\vec0)\) comes out to that fixed vector instead of \(\vec0\). The same failure catches anything with a constant baked in, like \(T(\langle x,y\rangle)=\langle x, y+1\rangle\): \(T(\vec0)=\langle0,1\rangle\neq\vec0\), disqualified by the same one-line check.

Be careful with the converse, though: passing the \(T(\vec 0)=\vec 0\) test is necessary, not sufficient. For example \(T(\langle x,y\rangle) = \langle x^2, y\rangle\) does send \(\langle0,0\rangle\) to \(\langle0,0\rangle\) — and is still not linear. Check additivity with \(u=v=\langle1,0\rangle\): \(T(u+v)=T(\langle2,0\rangle)=\langle4,0\rangle\), but \(T(u)+T(v)=\langle1,0\rangle+\langle1,0\rangle=\langle2,0\rangle\). \(4\neq2\) — it fails anyway, just not on the fast test. The zero-vector check is a good first move for ruling things out quickly; it can never fully confirm linearity on its own.

Try it yourself

Is a translation — adding a fixed nonzero vector to the input, like \(T(\langle x,y\rangle)=\langle x+3,\ y-1\rangle\) — a linear transformation?

Practice

  1. Is \(T(\langle x,y\rangle) = \langle 3x,\ -y\rangle\) linear? (Check both conditions, or reason from its structure.)
    Yes — both additivity and homogeneity hold (each output coordinate is just a constant times an input coordinate, which always distributes correctly over sums and scalars).
  2. Is \(T(\langle x,y\rangle) = \langle x,\ y,\ 1\rangle\) (mapping into 3D) linear?
    No — fast test: \(T(\langle0,0\rangle)=\langle0,0,1\rangle\neq\langle0,0,0\rangle\).
  3. Is \(T(x) = 5x\) (a function of a single real number) linear?
    Yes — \(T(x_1+x_2)=5(x_1+x_2)=5x_1+5x_2=T(x_1)+T(x_2)\), and \(T(cx)=5cx=c(5x)=cT(x)\). Scaling by a constant is always linear, in any dimension.
  4. Is \(T(\langle x,y\rangle) = \langle xy,\ x\rangle\) linear?
    No. With \(u=v=\langle1,1\rangle\): \(T(u+v)=T(\langle2,2\rangle)=\langle4,2\rangle\), but \(T(u)+T(v)=\langle1,1\rangle+\langle1,1\rangle=\langle2,2\rangle\). Multiplying two coordinates together always breaks linearity.
  5. Is \(T(\langle x,y\rangle) = \langle y,\ x\rangle\) (swapping coordinates) linear?
    Yes — this is reflection over the line \(y=x\), a genuine linear transformation (common as an axis-swap in engine code).
  6. Is \(T(\langle x,y\rangle) = \langle x-2,\ y+2\rangle\) linear?
    No — it's a translation. \(T(\langle0,0\rangle)=\langle-2,2\rangle\neq\langle0,0\rangle\).
  7. bonus — Is \(T(\langle x,y\rangle) = \langle 2x+3y,\ x-y\rangle\) linear?
    Yes — every output coordinate is a sum of constants times input coordinates (exactly the shape Chapter 2 will show always comes from a matrix).
  8. bonus — Is \(T(\langle x,y\rangle) = \langle |x|,\ y\rangle\) linear?
    No — homogeneity fails for negative scalars: \(T(-1\cdot\langle x,y\rangle)=T(\langle-x,y\rangle)=\langle|x|,y\rangle\), but \((-1)T(\langle x,y\rangle)=\langle-|x|,-y\rangle\). These aren't equal whenever \(x\neq0\) or \(y\neq0\) — an "absolute value" step in engine code is a classic hidden source of non-linearity.
  9. bonus — Is \(T(\langle x,y,z\rangle) = x+y+z\) (summing all three coordinates into one number) linear?
    Yes — sums always distribute over vector addition and pull scalars out cleanly, so any "add up the coordinates" function is linear.
  10. bonus — If a transformation fixes the origin (\(T(\vec 0)=\vec 0\)), is that enough on its own to guarantee it's linear?
    No — necessary, not sufficient. \(T(\langle x,y\rangle)=\langle x^2,y\rangle\) fixes the origin but still fails additivity (see the mistake block above).
  11. challenge — Let \(A\) be any fixed matrix and define \(T(x) = Ax\) (matrix-vector multiplication). Using the distributive and scalar properties of matrix multiplication, prove \(T\) is automatically linear for every choice of \(A\) — no specific numbers needed.
    Additivity: \(T(u+v) = A(u+v) = Au+Av = T(u)+T(v)\), using the distributive law for matrix multiplication over vector addition. Homogeneity: \(T(cu) = A(cu) = c(Au) = cT(u)\), pulling the scalar through matrix multiplication. Both hold for any matrix \(A\) — so every matrix automatically defines a linear transformation. Chapter 2 proves the converse: every linear transformation comes from some matrix, meaning "linear transformation" and "matrix" turn out to be exactly the same idea seen from two directions.
