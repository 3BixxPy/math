Solving Logarithmic Equations

Chapter 8 solved for a variable trapped in an exponent by taking a log. This chapter runs the same idea in reverse — a variable trapped inside a log gets freed by converting back to exponential form — with one extra, non-optional step at the end.

Why this matters

Solving a log equation is really three chapters of this module used back to back: condense every log term into one (Chapters 6–7's laws), convert that single log equation into exponential form (Chapter 4's definition), then solve algebraically. The genuinely new idea here isn't algebraic at all — it's a domain check. Logs are only defined for positive arguments (Chapter 4), so every candidate solution has to be checked against the original equation before it counts as valid.

Method — Solving log equations
  1. Condense all log terms on one side into a single log, using the product/quotient/power rules (Chapters 6–7).
  2. Rewrite the resulting log_b(expression) = c as expression = b^c (Chapter 4's definition).
  3. Solve the resulting equation for the variable.
  4. Check every solution in the original equation — reject any that make a log's argument zero or negative.
Rule — The domain check is not optional
\[ \log_b(\text{argument}) \text{ is defined only when argument} > 0 \]
(3.9.1)

Converting to exponential form (step 2 above) and solving algebraically can produce a number that satisfies the converted equation but makes one of the original logs undefined. That number is called an extraneous solution — it has to be thrown out, not because the algebra was wrong, but because it was never a valid input to begin with.

Worked example — condense, convert, solve, check

Solve log(x) + log(x-3) = 1.

Step 1 — condense using the product rule (Chapter 6)

\(\log(x)+\log(x-3) = \log\big(x(x-3)\big) = 1\)

Step 2 — convert to exponential form (Chapter 4; base 10, since this is a common log)

\(x(x-3) = 10^1 = 10\)

Step 3 — solve the resulting quadratic (Module 0, Chapter 13)

\(x^2-3x-10=0 \Rightarrow (x-5)(x+2)=0 \Rightarrow x=5 \text{ or } x=-2\)

Step 4 — check both against the original log's domain

Original equation needs \(x>0\) and \(x-3>0\), i.e. \(x>3\). \(x=5\): \(5>3\) ✓ valid. \(x=-2\): fails immediately — \(\log(-2)\) isn't even defined. Reject it.

Result

\(x=5\) is the only solution — \(x=-2\) is extraneous, a byproduct of squaring-like structure introduced when the quadratic formed, not a real solution to the original equation.

Common mistake

Solving the algebra correctly and then reporting every root as a final answer, without checking each one's argument back in the original log equation. This is exactly where extraneous solutions hide — the converted exponential equation (step 2 above) has no memory of the domain restriction the original log equation carried, so it will happily hand back a root that makes a log's argument zero or negative. The check in step 4 isn't a formality; skipping it is the single most common way to get a log-equation problem wrong despite doing the algebra perfectly.

Practice

  1. Solve: log_3(x) = 4
    \(x=3^4=81\)
  2. Solve: ln(x) = 2 (leave in terms of e)
    \(x=e^2\)
  3. Solve: log(x) + log(4) = log(20)
    \(\log(4x)=\log(20) \Rightarrow 4x=20 \Rightarrow x=5\)
  4. Solve: log_2(x+1) = 5, and check it's valid.
    \(x+1=2^5=32 \Rightarrow x=31\); check: \(31+1=32>0\) ✓
  5. Solve: log(x) − log(2) = 1
    \(\log(x/2)=1 \Rightarrow x/2=10 \Rightarrow x=20\)
  6. Solve log(x) + log(x+3) = 1 and identify any extraneous root.
    \(\log(x(x+3))=1 \Rightarrow x^2+3x-10=0 \Rightarrow (x+5)(x-2)=0 \Rightarrow x=2 \text{ or } x=-5\). Domain needs \(x>0\), so \(x=-5\) is extraneous; only \(x=2\) is valid.
  7. bonus — Solve: ln(2x) = 0
    \(2x=e^0=1 \Rightarrow x=1/2\)
  8. bonus — Solve: 2·log(x) = log(36)
    \(\log(x^2)=\log(36) \Rightarrow x^2=36 \Rightarrow x=\pm6\); domain needs \(x>0\), so only \(x=6\) is valid — \(x=-6\) is extraneous.
  9. bonus — Solve log_2(x) + log_2(x-2) = 3 and check both candidate roots.
    \(\log_2(x(x-2))=3 \Rightarrow x(x-2)=8 \Rightarrow x^2-2x-8=0 \Rightarrow (x-4)(x+2)=0 \Rightarrow x=4 \text{ or } x=-2\). Domain needs \(x>2\); \(x=4\) valid, \(x=-2\) extraneous.
  10. bonus — Why can a quadratic step (like factoring \(x^2-2x-8\)) introduce an extraneous root into a log equation, when the same quadratic on its own would have two perfectly good roots?
    The quadratic itself is fine and has two legitimate roots — the extraneousness comes entirely from the original log's domain restriction, which the quadratic (after converting away from log form) no longer "remembers." One root can satisfy the quadratic while violating a restriction that only existed in the un-converted version.
  11. challenge — Solve log_2(x-1) + log_2(x+1) = 3 for x, showing the full condense → convert → solve → check pipeline, and explain in one sentence why the domain check here rules out a root that's a "nice" integer.
    Condense: \(\log_2\big((x-1)(x+1)\big)=\log_2(x^2-1)=3\). Convert: \(x^2-1=2^3=8 \Rightarrow x^2=9 \Rightarrow x=\pm3\). Check domain: needs \(x-1>0\) and \(x+1>0\), i.e. \(x>1\). \(x=3\) is valid; \(x=-3\) is a perfectly "nice" integer but still extraneous, because \(-3-1=-4<0\) makes the original log undefined — being a clean number doesn't exempt a root from the domain check.
