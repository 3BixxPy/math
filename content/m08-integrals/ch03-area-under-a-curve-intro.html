Area Under a Curve — the Estimation Problem

Set the antiderivative toolkit aside for a moment. This chapter starts on something that looks completely different: finding the exact area trapped between a curve and the x-axis.

Why this matters

The area of a rectangle is base times height. The area of a triangle is half of that. Even oddly-shaped polygons reduce to a handful of triangles. But a region bounded by a genuine curve — say, the area under y = x² from 0 to 2 — has no polygon formula to fall back on. There's no obvious "exact" answer at all yet, only a question worth taking seriously: can it even be pinned down precisely, and if so, how?

The natural move is to approximate the region with shapes that do have a known area — rectangles — and get more honest about it than a single guess. Slice the interval [a,b] into n equal pieces of width Δx = (b−a)/n, and on each piece, build a rectangle as tall as the curve at one particular x-value in that piece:

  • Left-endpoint rule — use the height of the curve at the left edge of each piece.
  • Right-endpoint rule — use the height of the curve at the right edge of each piece.

Neither one is exactly right — a rectangle's flat top can't match a curved top perfectly — but summing the rectangles' areas gives a number that's at least in the right neighborhood. The question worth exploring first: what happens to that number as the rectangles get thinner and more numerous?

n = 4, left-endpoint estimate ≈ 1.7500

f(x) = x² on [0, 2]. Drag the slider, and switch between left- and right-endpoint rectangles.

Worked example

Approximate the area under f(x) = x² on [0, 2] using 4 rectangles, both left- and right-endpoint.

Step 1 — find Δx and the four subinterval edges

\(\Delta x = \dfrac{2-0}{4} = 0.5\). Edges: \(0,\ 0.5,\ 1,\ 1.5,\ 2\).

Step 2 — left-endpoint sum (use the left edge of each piece: 0, 0.5, 1, 1.5)

Heights: \(f(0)=0,\ f(0.5)=0.25,\ f(1)=1,\ f(1.5)=2.25\). Sum: \((0+0.25+1+2.25)\times0.5 = 3.5\times0.5 = 1.75\).

Step 3 — right-endpoint sum (use the right edge of each piece: 0.5, 1, 1.5, 2)

Heights: \(f(0.5)=0.25,\ f(1)=1,\ f(1.5)=2.25,\ f(2)=4\). Sum: \((0.25+1+2.25+4)\times0.5 = 7.5\times0.5 = 3.75\).

Result — the estimates bracket the true value

Left estimate \(1.75\), right estimate \(3.75\) — since \(f(x)=x^2\) is increasing on \([0,2]\), the true area has to sit somewhere between them: \(1.75 \le \text{true area} \le 3.75\). Neither one alone is exact, but together they trap it.

Common mistake

Assuming left- and right-endpoint estimates are equally (in)accurate no matter what the function looks like. They're not — it depends entirely on whether the function is increasing or decreasing. For an increasing function (like the worked example), the left edge of each piece is always the shortest point on that piece and the right edge the tallest, so left-endpoint always underestimates and right-endpoint always overestimates. For a decreasing function, it's exactly reversed: left overestimates, right underestimates. There's no universal rule like "left is always smaller" — it flips with the function's direction.

Practice

  1. f(x) = x on [0, 4], n = 2. Find the right-endpoint estimate.
    \(\Delta x=2\); right edges \(2,4\); heights \(2,4\); sum \(=(2+4)(2)=12\).
  2. Same function and interval as above. Find the left-endpoint estimate.
    Left edges \(0,2\); heights \(0,2\); sum \(=(0+2)(2)=4\). (True area, a triangle, is \(8\) — this brackets it: \(4\le8\le12\).)
  3. f(x) = 3 (constant) on [0, 5], n = 5. Find the right-endpoint estimate.
    \(15\) — for a constant function, left and right endpoints give the exact same (exact) answer every time, no approximation error at all.
  4. f(x) = x² on [0, 1], n = 2. Find the left-endpoint estimate.
    \(\Delta x=0.5\); left edges \(0,0.5\); heights \(0,0.25\); sum \(=(0+0.25)(0.5)=0.125\).
  5. f(x) = 4 − x (a decreasing function) on [0, 4], n = 2. Find the right-endpoint estimate, and state whether it over- or underestimates the true area.
    Right edges \(2,4\); heights \(2,0\); sum \(=(2+0)(2)=4\). True area (a triangle) is \(8\) — right-endpoint underestimates here, matching the mistake block's rule for a decreasing function.
  6. For a decreasing function, does left-endpoint overestimate or underestimate the true area? Justify briefly.
    Overestimates — the left edge of each piece is the tallest point on a decreasing piece, so every rectangle sits above the curve.
  7. bonus — f(x) = 2x on [0, 3], n = 3. Find the left-endpoint estimate.
    \(\Delta x=1\); left edges \(0,1,2\); heights \(0,2,4\); sum \(=(0+2+4)(1)=6\).
  8. bonus — Same function and interval as above. Find the right-endpoint estimate, and confirm both bracket the true area of \(9\).
    Right edges \(1,2,3\); heights \(2,4,6\); sum \(=(2+4+6)(1)=12\). Bracket: \(6\le9\le12\) ✓.
  9. bonus — If a function is constant on an interval, what's true about its left- and right-endpoint estimates, no matter how many rectangles are used?
    They're equal to each other, and both equal the true area exactly — a constant function has no approximation error to begin with.
  10. bonus — f(x) = x² on [0, 1], n = 4. Find the right-endpoint estimate.
    \(\Delta x=0.25\); right edges \(0.25,0.5,0.75,1\); heights \(0.0625,0.25,0.5625,1\); sum \(=(1.875)(0.25)=0.46875\).
  11. challenge — For f(x) = x on [0, b] with a general n (not a specific number), write the right-endpoint sum and simplify it using 1+2+⋯+n = n(n+1)/2. What value does it approach as n → ∞, and does that match the known triangle-area formula?
    \(\Delta x=b/n\), right edges \(x_i=ib/n\). Sum \(=\displaystyle\sum_{i=1}^n \frac{ib}{n}\cdot\frac{b}{n} = \frac{b^2}{n^2}\sum_{i=1}^n i = \frac{b^2}{n^2}\cdot\frac{n(n+1)}{2} = \frac{b^2(n+1)}{2n}\). As \(n\to\infty\), \(\frac{n+1}{n}\to1\), so the sum \(\to \frac{b^2}{2}\) — exactly \(\frac12\cdot b\cdot b\), the ordinary triangle-area formula. The rectangles really do converge to the right answer.
